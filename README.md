# Tracker — общий план команды

GitHub Pages размещает интерфейс, Supabase хранит общий план и передаёт изменения всем открытым вкладкам. Любой посетитель ссылки может редактировать план — это намеренная модель доступа.

## Использование

- Кнопка «＋ Задача» создаёт задачу в выбранном спринте и продукте активной задачи; крестик удаляет её, «Вернуть» восстанавливает.
- Редактирование названий и продуктов — прямо в таблице. Цвета продуктов общие, переключатели видимости индивидуальные.
- Перетаскивание и изменение длины полоски — с шагом в спринт.
- Задачи одного продукта всегда собраны вместе; при смене продукта задача переходит в его группу. Порядок задач меняется за ручку ⠿ или неактивное название слева, только в пределах одного продукта. На ручке также работают Alt + ↑/↓. Спринты при этом не меняются, порядок общий для всех.
- Участники и проценты относятся к выбранной задаче. Перегрузка считается по сумме всех задач.
- Каждый спринт показывает общую загрузку команды и красную точку, если хотя бы один участник загружен больше 100%.
- Alt + ←/→ меняет горизонтальный масштаб, Alt + ↑/↓ — вертикальный, Alt + 0 сбрасывает его.
- Полугодовой таймлайн, закрепление колонки задач и сворачиваемые исполнители.
- Значок ↓ скачивает резервную копию JSON.

## Постоянное хранение

Задачи, назначения, проценты, удаления и цвета продуктов сохраняются в базе Supabase. Очистка браузера не удаляет подтверждённые изменения. Масштаб, выбранная задача, фильтры и вид панелей остаются персональными.

Интерфейс обновляется мгновенно, отправка правок выполняется в фоне с небольшой задержкой. При потере сети изменения остаются в локальной очереди до восстановления связи. Не очищайте данные сайта, пока статус не показывает «Сохранено в общей базе»: ещё не отправленные изменения существуют только на этом устройстве.

Изменения отдельных полей и назначений сливаются независимо. При редактировании одного и того же поля применяется последняя полученная сервером правка. Удаление мягкое: запоздалые правки не воскрешают задачу. Повторная отправка операции безопасна.

## Перенос старого локального плана

Откройте обновлённую локальную версию по прежнему адресу в том же браузере, где вы планировали. Нажмите «Перенести локальный план». Это явный перенос: случайный посетитель со старым кэшем не может автоматически заменить общий план. Перед переносом можно скачать резервную копию кнопкой ↓.

## Разработка и публикация

```sh
npm ci --ignore-scripts
npm test
npm run build
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

GitHub Actions публикует dist/ в GitHub Pages после изменений main. Для Pages из приватного репозитория аккаунту требуется подходящий тариф GitHub; видимость репозитория автоматически не меняется.

В dist/config.js находится только публичный publishable key, не секретный service_role. RLS ограничивает доступ одним общим планом. database/schema.sql содержит схему, права и идемпотентную функцию обновления. Изменения таблиц транслируются через Supabase Realtime, дополнительно выполняется сверка каждые 5 секунд и при возвращении во вкладку.
